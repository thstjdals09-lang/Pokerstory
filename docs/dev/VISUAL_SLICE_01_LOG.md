# Visual Vertical Slice 01 — 첫 플레이 대표 구간 기록

- 브랜치: `feature/visual-slice-01` (기준: Content Finishing이 병합된 `main`). main 병합은 하지 않음.
- 범위: 마을 광장, 카드룸, 내 집. 캐릭터는 플레이어, 루미, 모아, 세라. 그 밖의 지역과 주민은 그레이박스 그대로.
- 게임 규칙, 데이터 위치, 세이브 형식은 바꾸지 않음. 그림은 기존 데이터 좌표 위에 얹는 표현 층.

## 시각 기준(스케일)

| 항목 | 값 |
|---|---|
| 월드 타일 | 32px (바닥 텍스처는 128px 단위로 반복) |
| 캐릭터 키 | 72px(약 2.25타일). 모아 56px(떠 있음), 세라 88px |
| 문 폭 | 약 48px(1.5타일) |
| 화면 | 1280x720 기준, 한 화면에 약 40x22타일. `canvas_items` + `expand`로 확대(1920x1080에서 확인) |
| 원본 해상도 | SVG를 표시 크기의 2배로 제작 |

실루엣 구분: 루미는 여우 귀와 꼬리에 주황색, 모아는 날개가 달리고 떠 있는 작은 요정, 세라는 키가 크고 보라색 로브를 입음. 플레이어는 갈색 머리에 노란 코트와 청록 목도리.

## 자산 구조

```
game/assets/art/
  world/       바닥 타일 (grass, cobble, plaza, floor_cardroom, floor_home)
  buildings/   건물 외관 (home_player, shop_sera, card_room, hall, gate)
  characters/  player, lumi, moa, sera
  props/       나무, 분수, 가로등, 벤치, 화단, 게시판, 표지판, 입간판, 부스, 상자, 화분
  interiors/   카드룸, 집 벽과 가구, 포커 테이블, 의자, 칩 선반, 러그, 설계도
  items/       lamp_small (배치 아이템은 "item.<아이템 id>" 키)
  ui/          chip, sun, moon
game/data/art.json    키 → 파일, 표시 크기, 기준점, 빛, 깊이 정렬 여부, 초상화 영역
tools/art/make_slice_art.py   위 SVG를 전부 만드는 스크립트 (외부/유료 자산 없음)
```

- 게임 데이터(locations.json, npcs.json)에는 `"art": "bld.card_room"`처럼 키만 적음. 파일을 바꾸거나 지우면 해당 물체는 그레이박스 그림으로 돌아감.
- 그림에 게임 로직을 넣지 않음. 충돌, 문, 상호작용 반경은 기존 데이터 그대로.
- 빛은 art.json의 `lights`(창문, 가로등, 등불)와 장소별 `art.lights`로 정함. 낮/저녁 색조는 장소별 `day_tint` / `evening_tint`로 정함.

## 바뀐 것

| 영역 | 내용 |
|---|---|
| 광장 | 풀밭, 돌길, 원형 광장 타일. 건물 4채와 관문 그림. 나무, 분수, 가로등 6개, 루미 자리 벤치, 화단, 게시판, 부스. 저녁에는 푸른 색조에 창문과 가로등 빛이 들어오고, 카드룸 창과 입구 등이 가장 밝음 |
| 카드룸 | 나무 바닥과 문양 액자가 걸린 벽. 둥근 러그, 펠트 테이블, 의자, 칩 선반, 찻상, 옷걸이, 관전 벤치. 테이블 위 등을 중심으로 따뜻한 빛 |
| 내 집 | 나무 바닥, 벽, 창문. 침대, 탁자, 보관함, 러그, 이삿짐 상자(첫 단계에서만), 설계도. 창가에 등불을 놓으면 저녁에 방 윗부분이 밝아지고 낮에도 약하게 켜짐 |
| 캐릭터 | 네 명 모두 그림 스프라이트로 그리고 발밑 그림자를 넣음. 모아는 떠서 흔들리고, 플레이어는 걸을 때 흔들리며 좌우로 뒤집힘. 캐릭터 사이 깊이 정렬(y-sort) |
| 표시 | 상시 이름표 대신 가까이(220px)에서만 이름 표시(그림이 있는 장소 전체). 대상에 다가가면 발밑 고리와 종류 표시(… ↑ ♣ + z ! ✓). 플레이어 머리 위 이름은 숨김 |
| HUD | 칩 아이콘(장착한 칩 장식 색 반영), 해/달 아이콘과 장소 이름, 작은 목표 접기 버튼(▴/▾, Tab), 패널 그림자, 상호작용 안내는 어두운 알약 모양 |
| 대화 | 이름 탭과 초상화 칸(art.json의 `portrait` 영역). 초상화가 없는 화자는 글만 표시 |
| 포커 | 방과 나무 테두리, 초록 펠트 테이블. 상대와 나의 이름패와 초상화, 판돈을 칩 더미로 표시. 카드 앞면(양쪽 모서리 표기, J/Q/K 틀), 뒷면(격자와 클럽 문장, 장착한 뒷면 색). 기능, 버튼, 문구는 그대로 |

## 스크린샷
`docs/screenshots/visual_slice_01/` 아래 17장. 테스트 시나리오 `slice`(창 모드)로 다시 만들 수 있음:
`godot --path game -- --e2e=slice --save-path=user://e2e_slice.json --shots=<절대 경로>`

## 남은 시각 질문
- 캐릭터 72px이 광장 한 화면에 적당한지, 건물 대비 조금 작게 보이지 않는지
- 저녁 가로등 빛이 풀밭에서 약간 연둣빛으로 보임(가산 조명 특성). 색을 더 주황 쪽으로 할지
- 집 첫 단계가 너무 비어 보이는지. 등불 하나로 달라지는 정도가 충분한지
- 등불 배치 칸이 창틀 위에 겹쳐 그려짐. 창턱 선반을 그릴지
- 이름표를 가까이에서만 보이게 한 것이 그레이박스 주민(도형)에게는 불편한지
- 초상화를 스프라이트에서 잘라 쓰는 방식을 유지할지, 표정이 있는 전용 초상화를 따로 둘지
- 포커 판돈 칩 더미의 위치(테이블 오른쪽)와 결과 창 겹침
