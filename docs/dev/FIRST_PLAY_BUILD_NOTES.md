## 1. 실행 방법

1. Godot 4.7.2를 받습니다: [4.7.2-stable 릴리스](https://github.com/godotengine/godot/releases/tag/4.7.2-stable)의 `Godot_v4.7.2-stable_win64.exe.zip`
2. 다음 중 하나로 실행합니다.
   - 저장소 루트의 `run_game.bat`을 실행합니다. 기본 경로는 `%USERPROFILE%\tools\godot\`이고, 다른 경로면 환경 변수 `GODOT`에 exe 경로를 지정합니다.
   - 명령줄: `Godot_v4.7.2-stable_win64.exe --path game`
   - 에디터: Godot에서 `game/project.godot`를 열고 F5를 누릅니다.

독립 실행 파일(.exe) 내보내기는 아직 하지 않았습니다. 이유는 6절을 참고하세요.

### 조작

| 입력 | 동작 |
|---|---|
| WASD / 방향키 | 이동 |
| E / Enter | 대화, 문 출입, 대화 넘기기. 화면 아래 프롬프트 버튼을 눌러도 같습니다. |
| Esc | 메뉴 / 뒤로 / 창 닫기 |
| Tab | 현재 목표 접기·펼치기 |
| 마우스 | 카드 선택, 버튼, 집 꾸미기 자리 선택 |
| 1~5 | 포커 카드 선택, 대화 선택지 고르기 |

## 2. 구조

```
game/
├─ project.godot            엔진 설정 (4.7 고정, autoload "Game")
├─ data/                    게임 데이터 — 콘텐츠 추가 시 코드 수정 불필요
│  ├─ locations.json        4개 공간: 지형, 건물, 문, 표지판, 주민 배치, 가구 자리
│  ├─ npcs.json             주민 3명 (이름, 종족, 임시 외형)
│  ├─ dialogue.json         조건부 대화 (위에서부터 첫 번째로 맞는 항목을 표시)
│  ├─ items.json / shops.json
│  ├─ poker.json            룰, 보상, 능력, 상대 대사, 족보 도움말
│  └─ goals.json            HUD 현재 목표 (조건부)
├─ scripts/
│  ├─ core/                 엔진 노드에 의존하지 않는 순수 로직 (단위 테스트 대상)
│  │  ├─ card, deck         52장 덱, 시드 셔플, 테스트용 스택 덱
│  │  ├─ hand_evaluator     5장 족보 판정 (순수 함수)
│  │  ├─ poker_ai           루미의 공개 교체 규칙 (자기 패만 받음)
│  │  ├─ poker_match        한 판 진행: 딜 → 능력 → 교체 → 승부
│  │  ├─ poker_rewards      정산 (1회만 지급, 첫 참가 보너스 1회)
│  │  ├─ game_state         저장 대상 상태 전체, 칩 원장
│  │  ├─ save_system        단일 슬롯 JSON, 버전 필드, 임시 파일 → 교체 방식 쓰기
│  │  ├─ conditions, dialogue_resolver, data_db, geo
│  ├─ autoload/game.gd      세션: 데이터, 상태, 저장, UI가 호출하는 규칙 동작
│  ├─ world/                공간 그리기, 충돌, 플레이어, 주민, 상호작용 판정
│  ├─ ui/                   타이틀, HUD, 튜토리얼, 대화, 포커, 상점, 집 꾸미기, 메뉴·도감
│  └─ main.gd               화면 흐름과 입력 모드 전환
├─ scenes/main.tscn         진입 씬 (나머지는 코드와 데이터로 구성)
└─ tests/
   ├─ run_tests.gd          단위 테스트 실행기
   ├─ unit/                 족보, 덱·AI, 판 진행, 상태·보상, 저장, 데이터·대화
   └─ e2e/first_play_e2e.gd 실제 게임을 처음부터 끝까지 조작하는 자동 플레이
```

**입력 모드 분리:** `main.gd`의 `ui_mode`(world / dialogue / poker / shop / home_edit / menu / title / transition)가 입력을 받을 대상을 정합니다. 플레이어는 `world` 모드에서만 움직일 수 있어서 포커 중 이동 조작과 충돌하지 않습니다(명세 3절).

## 3. 명세 6절 상태 항목과 저장 파일의 대응

저장 위치: `user://save_slot_1.json`. Windows에서는 `%APPDATA%\Godot\app_userdata\Pokerstory\`입니다.

| 명세 항목 | 저장 파일 키 | 비고 |
|---|---|---|
| `save_version` | `save_version` | 현재 1. 더 새로운 버전과 지원하지 않는 이전 버전은 거부하고 파일을 건드리지 않음 |
| `player_name` | `player_name` | 비우면 "여행자" |
| `chips_balance` | `chips_balance` | 음수 불가 (`spend_chips`가 거부) |
| `chips_ledger` | `chips_ledger[]` | `{seq, delta, reason, balance}` |
| `intro_met_lumi` | `flags.intro_met_lumi` | 플래그는 `flags` 객체 하나에 모음 |
| `first_poker_bonus_claimed` | `flags.first_poker_bonus_claimed` | |
| `lumi_lamp_reaction_seen` | `flags.lumi_lamp_reaction_seen` | |
| `poker_hands_completed` | `poker_hands_completed` | 승·무·패 횟수는 `poker_record`에 따로 저장 |
| `owned_items[]` | `owned_items` | `{item_id: 보관 수량}` (배치하지 않은 것만) |
| `home_placements[]` | `home_placements[]` | `{slot, item}` |
| `current_scene` | `current_scene` | 이어하기 시 이 장소와 `player_position`으로 복귀 |
| (추가) 도감 | `collection[]` | 처음 얻은 아이템 ID |

**저장 시점:** 새 게임 시작, 장소 이동, 주요 대화 플래그 변경, 포커 정산, 구매, 가구 배치·회수, 메뉴 저장, 타이틀로 이동, 종료(창 닫기 포함).
**중간 종료:** 포커 도중 강제 종료하면 그 판은 무효입니다(칩 변화 없음, 판 수 미포함). 정산은 판이 끝나는 즉시 저장되므로 첫 참가 보너스는 두 번 지급되지 않습니다.

## 4. 검증 결과

### 4.1 실행 명령

```bash
tools/run_tests.sh          # unit + e2e 전체 (Git Bash). GODOT 환경 변수로 경로 지정 가능
tools/run_tests.sh unit
tools/run_tests.sh e2e
```

### 4.2 결과 (2026-09-25, Windows 10, Godot 4.7.2)

| 묶음 | 결과 |
|---|---|
| 단위 테스트 | 41개 통과 / 0개 실패 |
| E2E `win` | 161개 검증 통과 |
| E2E `draw` | 160개 검증 통과 |
| E2E `lose` | 160개 검증 통과 |
| E2E `resume_a` → `resume_b` → `resume_c` (프로세스 3개) | 12 / 26 / 9개 검증 통과 |
| E2E `reject` | 7개 검증 통과 |
| 창 모드 E2E `win` + 스크린샷 | 161개 검증 통과 (NVIDIA RTX 2060 SUPER, OpenGL 3.3) |

로그의 `ERROR: Parse JSON failed`는 손상된 저장 파일을 일부러 읽히는 테스트에서 나오는 정상 출력입니다.

### 4.3 E2E가 실제로 하는 일

- 타이틀에서 새 게임을 시작하고 이름을 입력하는 것부터 시작합니다.
- 이동은 실제 입력 액션으로 합니다(`move_up` 누르기, 건물 충돌 확인).
- 대화·출입은 실제 `interact` 입력 이벤트로 합니다. 월드의 근접 판정이 올바른 대상을 잡는지도 확인합니다.
- 버튼과 카드는 마우스 클릭이 발생시키는 것과 같은 `pressed` 신호로 누릅니다.
- **대상까지 걸어가는 과정은 생략하고 플레이어를 대상 옆으로 옮깁니다.** 걷기 자체는 이동·충돌 검증에서 따로 확인합니다.
- 포커 결과를 정하기 위해 테스트 전용 스택 덱(`Game.debug_deck_queue`)을 씁니다. 실제 플레이는 무작위 시드 덱을 쓰고, 시드는 콘솔에 `[poker] deck seed N`으로 출력됩니다.

### 4.4 Gate 1 수용 조건 대응

| 수용 조건 | 검증 방법 | 결과 |
|---|---|---|
| 전체 루프 (마을 → 루미 → 포커 → 보상 → 상점 → 배치 → 반응) | E2E win/draw/lose | 통과 |
| 승·무·패 각각의 보상과 구매 가능성 | E2E 3종 + 단위 `test_first_hand_always_affords_the_lamp` | 첫 판 후 100 / 70 / 60칩, 모두 50칩 등불 구매 가능 |
| 중간 종료 후 재진입, 보너스 1회 | E2E resume_a/b/c (별도 프로세스) | 통과 |
| 중복 정산 없음 | 단위 `test_a_hand_is_paid_only_once` | 통과 |
| 음수 칩 없음 | 단위 `test_chips_never_go_negative`, E2E 원장 검사 | 통과 |
| 세이브 유실 없음 | 단위 저장 테스트 (임시 파일, 백업), E2E 재시작 | 통과 |
| 족보 오판 없음 | 단위 `test_hand_evaluator.gd` (9개 족보, 키커, 휠, 에이스 순환 불가, 무승부) | 통과 |
| 숨은 정보 악용 없음 | 상대 카드는 승부 전까지 UI에 전달되지 않음(E2E), AI는 자기 패만 받음(단위 `test_opponent_ignores_player_hand`), 별빛 감각은 참/거짓 하나만 반환 | 통과 |
| 구버전·신버전 세이브 처리 | 단위 저장 테스트, E2E reject | 거부 + 안내 메시지 + 파일 보존 |

## 5. P0~P8 구현 현황

| 단계 | 구현 | 비고 |
|---|---|---|
| P0 도착 | ✅ | 타이틀 → 이름 입력(기본값 "여행자") → 마을 입구. 튜토리얼은 이동·대화 2단계, 건너뛰기 가능 |
| P1 인사 | ✅ | 루미 첫 대화에서 플래그 저장, 반복 대사가 달라짐, 새 대사가 있으면 "!" 표시 |
| P2 자유 시간 | ✅ | 강제 없음. 포커 초대는 카드룸 간판(♣ 포커 모임), 게시판, 루미 대화 선택지, HUD 목표로 언제든 확인 가능 |
| P3 포커 모임 | ✅ | 카드룸에 들어가면 저녁 조명으로 바뀜. 모아·루미의 선택지나 포커 테이블에서 시작. 대기 타이머 없음 |
| P4 짧은 승부 | ✅ | 5장 → 별빛 감각(선택) → 최대 3장 1회 교체 → 공개. "그대로 승부"만 눌러도 완주 가능 |

| P6 꾸미기 | ✅ | 세라 상점에서 50칩 등불 구매 → 집 보관함 → 3개 자리 중 하나에 배치/회수. 저장 후 재진입해도 유지 |
| P7 반응 | ✅ | 배치 후 루미가 "불빛"을 언급하는 반응 1회 → 이후 후속 대사. 세라도 반응(선택 추가). 도감에 등불 기록 |
| P8 자유 플레이 | ✅ | 반복 포커, 집 꾸미기, 메뉴 저장/타이틀/종료, 이어하기 |

## 6. 명세와 다르게 구현했거나 해석한 부분

| 항목 | 구현 | 이유 / 영향 |
|---|---|---|
| 루미의 위치 | 낮에는 광장, 카드룸에서는 테이블 옆 | 명세상 루미는 인사와 1:1 포커 상대를 모두 맡습니다. 스케줄 시스템이 없으므로 두 장소에 고정 배치했습니다. |
| 카드룸에서 나오면 마을은 다시 낮 | 전역 시간 없음 | 명세 6절(그레이박스에서 낮·밤 자동 진행 없음)을 따른 것입니다. 저녁 조명은 카드룸 안에서만 적용됩니다. |
| 도감 기록 시점 | 구매(획득) 시점 | P7은 반응 단계에 도감 기록을 적었지만, 수집은 획득 기준이 자연스러워서 이렇게 했습니다. 결과는 같습니다. |
| `owned_items` 형식 | 배열 대신 `{id: 수량}` | 같은 가구를 여러 개 살 때 대비. 명세가 형식을 개발팀 제안으로 열어 두었습니다. |
| 생활 의뢰 | **미구현** | 명세 P5 주석의 "간단한 생활 의뢰로 재획득"은 구현하지 않았습니다. 참가비 0 + 패배 시 20칩으로 칩을 다시 모을 수 있어 루프는 끊기지 않습니다. 필요하면 다음 단계에서 추가합니다. |
| 가구 종류 | 작은 등불 1종 | 명세 범위. 상점·보관함·도감은 목록 구조라 데이터만 추가하면 늘릴 수 있습니다. |
| 한글 폰트 | 시스템 폰트(맑은 고딕 등) 참조 | 에셋을 만들지 않기 위한 선택입니다. Windows에서는 문제없지만, 다른 OS나 내보내기 빌드 전에는 라이선스가 확인된 폰트를 포함해야 합니다. |
| 실행 파일 | 내보내기 안 함 | 내보내기 템플릿(대용량)이 필요하고, 명세상 배포 전 단계입니다. 요청하면 Windows용 .exe 내보내기 설정을 추가하겠습니다. |

## 7. 알려진 문제와 확인하지 못한 항목

- **사람이 직접 한 판 끝까지 플레이한 확인은 아직 없습니다.** 자동 플레이와 스크린샷으로만 확인했습니다. 조작감, 이동 속도, 대사 속도, 포커의 재미는 Gate 2에서 판단해야 합니다.
- E2E는 대상까지 걷는 경로를 생략합니다. 좁은 곳에 끼는 문제가 있을 수 있어 수동 확인이 필요합니다(아래 체크리스트).
- **창 모드 E2E 간헐 실패 1회 (원인 미확정).** 창 모드 실행 7회 중 1회에서, P7 직전부터 자동 입력 이벤트(interact, menu)가 연속으로 무시되어 11개 검증이 실패했습니다. 같은 조건(스크린샷 포함 4회, 미포함 2회)과 헤드리스(8회 이상)에서는 재현되지 않았습니다. 실행 중 창 포커스 변경 같은 외부 요인으로 추정하지만 확인하지 못했습니다. 사람이 플레이할 때 같은 증상(가까이 있는데 E가 먹지 않음)이 나오면 알려 주세요.
- 해상도: 1280×720 기준이고 창 크기를 바꾸면 가로로 늘어납니다(stretch: canvas_items / expand). 다른 비율에서의 UI 배치는 확인하지 않았습니다.
- 사운드와 애니메이션 프레임은 없습니다(그레이박스).
- 저장 슬롯은 1개입니다.

## 8. 수동 확인 체크리스트 (Gate 2용)

1. `run_game.bat` 실행 → 새 게임 → 이름 입력 → 마을 입구에서 시작하는가
2. WASD로 걸어서 광장의 루미("!" 표시)에게 가 E로 대화할 수 있는가
3. 카드룸(오른쪽 위, ♣ 간판)까지 걸어가 입장하면 저녁 분위기로 바뀌는가
4. 모아와 대화 → "한 판 해보기" → 카드 클릭으로 선택/해제, 별빛 감각, 교체하기, 결과 화면
5. 한 판 더 / 자리에서 일어나기 → 마을로 나가 세라의 잡화점(왼쪽 위, ♦)에서 등불 구매
6. 내 집(가운데 위, ♥) → 보관함 앞에서 E → 등불 선택 → 방의 자리 클릭 → 확정
7. 광장의 루미에게 다시 말 걸면 등불 이야기를 하는가
8. Esc → 저장하고 게임 종료 → 다시 실행 → 이어하기로 같은 상태가 되는가
