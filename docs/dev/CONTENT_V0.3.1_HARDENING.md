## 1. 저장 실패 트랜잭션

### 방식
- **공통 트랜잭션 `StateTransaction.run(state, change, save)`**(`game/scripts/core/state_transaction.gd`), 순서:
  1. 변경 전 상태를 `GameState.to_dict()`로 스냅샷합니다.
  2. 변경을 적용합니다.
  3. 저장합니다.
  4. 저장에 실패하면 `GameState.restore(snapshot)`로 **같은 객체를 변경 전 값으로 되돌리고** `save_failed`를 돌려줍니다.
  - 변경이 거절되면(칩 부족 등) 상태를 건드리지 않은 채 끝나므로 저장할 것이 없습니다.
  - 영속 변화가 없는 단계(아르바이트 중간 줍기)는 `skipped`로 저장을 생략합니다.
- **`Game._commit(change, undo_session)`**: 모든 영속 동작이 이 한 곳을 지납니다.
  - 칩 지출·지급, 상점 구매, 교환, 공공사업 후원, 집 확장, 가구 배치·회수.
  - 의뢰 수락·완료·보상, 아르바이트 완료 보상.
  - 포커 참가금(판 생성), 능력 사용, 정산, 포기, 대회 보상.
  - 대사·장면의 1회성 보상(`run_effects`), 착용, 추적 의뢰 변경, 시간 변경.
  - 상태와 함께 바뀐 세션 객체도 함께 되돌립니다: 아르바이트 진행(마지막 줍기 취소), 포커 판 객체(`settled`, 능력 사용·잠금).
- **화면 동작 — 상태를 되돌리고, 다시 하면 그때 한 번 적용됩니다.**
  - 공통: "저장하지 못해서 방금 한 일을 되돌렸어요. 다시 시도해 주세요." 안내가 뜹니다.
  - 상점과 집 꾸미기 패널은 각자 문구를 보여 줍니다.
  - 포커 정산 실패: 결과 패널이 "저장하지 못했어요 / 다시 저장하기"로 바뀝니다. 같은 쇼다운 결과로 다시 저장하며, 새로 섞지 않습니다. 저장될 때까지 자리에서 일어날 수 없습니다. 참가금은 걸린 상태로 남습니다.
  - 포기 실패: 자리에 그대로 있고 판이 이어집니다.
  - 판 생성 실패: 판도 참가금도 없습니다.
- 디스크 쪽은 기존 원자적 저장(임시 파일 → 교체)을 그대로 씁니다. 실패하면 이전 정상 파일이 남습니다.
- 저장하지 않는 동작은 새 게임 첫 저장, 장소 이동 기록, 구세이브 v2 예외 판입니다. 이 중 장소 이동만 실패해도 이전 위치에서 이어집니다.
- 테스트용 실패 주입: `Game.debug_fail_saves = N`이면 다음 N번의 저장이 실패합니다.

### 테스트로 찾은 버그 (수정)
- 포커 공개 기록(`poker_history`)을 불러올 때 족보·결과 필드가 지워지고 있었습니다. 저장했다 불러오면 '패턴 수첩'의 자주 보인 족보가 비었습니다. 필드를 보존하도록 고쳤고 단위 테스트를 추가했습니다.

### 검증
- 단위 `test_transactions.gd`: 복원 시 같은 객체 유지, 대표 변경의 실패 → 정확히 이전 상태 → 재시도 1회 적용 → 반복해도 추가 적용 없음.
  - 대상: 구매, 배치·회수, 공공사업, 집, 의뢰, 1회성 이벤트, 아르바이트 마지막 줍기, 참가금, 정산.
- E2E `savefail`(277개 확인): 실제 화면에서 저장 실패를 주입하고, 매번 두 가지를 확인한 뒤 같은 동작을 다시 해서 한 번만 적용되는지 봅니다.
  - 확인 1: 메모리 상태가 변경 전과 동일한지.
  - 확인 2: 저장 파일이 바뀌지 않았는지.
  - 대상 동작: 아르바이트 완료, 구매, 배치, 회수, 의뢰 수락·완료, 공공사업, 집 확장, 교환, 착용, 1회성 이벤트 보상, 포커 참가금, 포기, 정산(다시 저장), 대회 우승 보상.
  - 마지막에 디스크의 저장 내용과 메모리 상태가 같은지 확인합니다.

## 2. 경제 장기 진행 측정 (test_grant 없음)

E2E `economy`, 결과 파일 `user://economy_audit.json`.

- **방식**: 새 세이브 하나에서 화면이 호출하는 것과 같은 `Game` 동작만 사용했습니다.
  - 동작: 아르바이트, 의뢰·사건 수락·완료, 스토리 대사와 선택, 구매, 공공사업, 집 확장, 포커.
  - 칩 주입(`test_grant`)은 없고, 원장 음수 없음을 확인합니다.
- **플레이 정책**:
  1. 처음에 주민 16명과 인사합니다.
  2. 스토리를 진행할 수 있으면 진행합니다(스토리에는 칩이 들지 않습니다).
  3. 열린 의뢰·사건은 바로 합니다.
  4. 목표 목록에서 열린 첫 목표를 살 수 있으면 삽니다. 목표 순서: 등불 → 게시판 수선 → 집 1 → 우편함 화단 → 밤길 등불 → 광장 벤치 → 손님 객실 → 장터 가림막 → 집 2 → 카드룸 테이블 → 집 3 → 축제 장식.
  5. 살 수 없으면 아르바이트 4종을 번갈아 합니다.
  - 혼합 플레이: 아르바이트 전에 칩이 20 이상이면 카드룸 홈게임 1판을 합니다. 플레이어는 주민과 같은 공개 교체 규칙을 쓰고, 덱은 시드로 고정합니다.

## 3. 스토리·대사 충실도

01_world/04·05·06 대본의 명시 대사와 의도를 대조해 다음을 고쳤습니다.

| 장면 | 수정 |
|---|---|
| S1 `scn.missing_invitation` | 모아 대사를 대본 문장으로("분명 여기에 두었는데 봉투만 남았어요.") |
| S2A 우편함 | 대본의 "모아에게 봉투 전달 선택지(한 번의 대화로 완료)" 추가: 도장 발견 → `봉투를 모아에게 전하기` → 모아의 짧은 답(`scn.postbox_envelope`) |
| S6 둔치 | 루미 "대회에 안 나와도 저녁 모임에 앉아도 된다는 말부터 할게.", 카일 "순서를 정해 두면 새 사람도 경기 규칙을 알 수 있겠군요."를 대본 그대로. 어느 쪽도 틀리지 않았다는 지문 추가 |
| S10 후일담 | 카일 "규칙판 옆에 빈 자리를 남겨 두었습니다. 다음 사람을 위해서요."를 대본 그대로 |
| 축제 후 반응 | 루미·카일의 축제 반응이 후일담 대사를 그대로 반복하던 것을, 같은 결론(누가 이겼는가보다 다시 오는 사람들, 다음 사람을 위한 자리)을 이어받는 문장으로 교체 |

- 그대로 확인한 것:
  - 노아(S2A)·엘라(S2B)·루미·카일(S4)·미리·노아(S8)·루미(S10)의 대본 대사.
  - S3의 두 질문과 모아의 "물론".
  - S9의 네 선택지와 "참가하지 않아도 괜찮아요".
- 회귀 테스트 `test_story_fidelity.gd`는 명시 대사와 함께 메시지를 지키는 조건을 고정합니다.
  - 1막: 두 단서가 있어야 하고 포커 조건은 없음. 두 질문 모두 같은 긍정 답.
  - 2막: 세 답이 모두 화해로 이어지고 어느 쪽에도 관계 가감이 없음. 두 입장을 다 들어야 선택 가능.
  - 3막: 관전·정리·인사 모두 같은 엔딩이고, 대회 참가는 승리 없이 3막 완료. 기여 3개.
  - 후일담: 누구에게나 같은 아침. 반응 대사가 후일담 문장을 반복하지 않음.
