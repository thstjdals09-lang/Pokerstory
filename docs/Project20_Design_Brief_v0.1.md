## 2. 게임 경험의 중심축

- 포커는 마을 주민들의 **생활 문화 및 관계 형성 수단**이다. 게임 전체를 카지노 경영이나 현실 포커 훈련 시뮬레이터로 취급하지 않는다.
- 낮에는 생활·산책·대화·꾸미기·수집, 밤에는 홈게임·모임·특별 이벤트 등 포커 활동을 접할 수 있다. 이는 분위기상 기본 루프이지, 정해진 시각에 반드시 참여해야 하는 시간 제한 규칙은 아니다.
- 주민은 플레이어에게만 반응하는 기능성 NPC가 아니라 각자의 성격·생활·대인관계를 가진 존재로 지향한다.
- 개인 집을 꾸미고 마을 변화에 참여하며 수집품을 확보하는 장기 동기를 둔다. 모든 마을 시설을 플레이어가 직접 운영하는 경영 게임은 아니다.
- 게임 플레이의 목표와 강제 일과를 최소화하고, 원하는 활동을 스스로 고를 수 있게 한다.

## 3. 아이디어 예시 — **확정 사항 아님**

- 등장인물 아이디어: 칩 요정, 카드 유령, 포커를 즐기는 수인, 마법사 등.
- 공간 아이디어: 문양이 새겨진 광장, 포커를 즐기는 작은 가게, 주민들의 홈게임 장소.
- 능력 아이디어: 감정 힌트 확인, 한정적 카드 교체, 블러프 단서 등의 판타지 효과.
- 아이템 아이디어: 카드 덱, 칩, 의상, 가구, 주민 기념품.

위 항목은 콘셉트 이해를 돕기 위한 예시다. 캐릭터·맵·능력·아이템 목록 또는 제작 요구사항으로 해석하지 말 것.

## 4. 미결정 사항 — 임의 확정 금지

- 게임 정식 명칭, 출시 플랫폼 및 우선 플랫폼, 싱글/멀티플레이 여부, 온라인 기능.
- 엔진/프레임워크, 프로그래밍 언어, 그래픽 표현(2D/3D/픽셀아트 등), 카메라 시점과 입력 방식.
- 포커 기본 룰, 승패/보상 방식, 능력 효과·사용 제한·밸런스, 플레이 시간, 가상 재화 및 과금/현금 관련 설계.
- 월드 맵, 초기 주민 및 건물 수, 스토리, 퀘스트, 관계 시스템 상태 모델, 주거/마을 발전 규칙.
- 게임 내 시간의 실제 진행 로직, 현실 날짜 이벤트의 운영/재접근 방식, 저장 방식.
- 개발 일정, 인력, 예산, MVP 기능 목록 및 수량. 이전 대화에서 제안된 예시 MVP 수치는 사용자 확정 사항이 아님.

## 5. 현재 단계의 작업 경계

**이번 단계에 허용된 결과물:** 프로젝트 전용 저장소(또는 로컬 Git 저장소)와 최소한의 관리용 파일, 이 기획 문서의 보관, 준비 결과 보고.

**이번 단계에서 금지:** 게임 구현, 엔진 프로젝트 생성, 게임 시스템 설계 확정, 기능 스캐폴딩, UI/아트/맵/캐릭터 에셋 생성, 패키지 설치, 배포, 임의의 기술 스택 결정, 기존 저장소/파일 수정·삭제.

저장소 위치·이름·접근 권한 또는 GitHub 계정이 불명확하거나 실제 생성 권한이 없으면 임의로 대체하지 말고 필요한 사항만 질문할 것. 현재 사용자 요청은 **저장소 준비까지만**이며, 다음 개발 단계는 별도의 승인 후 진행한다.
