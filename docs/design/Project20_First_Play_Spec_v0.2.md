## 0. 결정 출처와 경계

- **사용자 확정**: 싱글플레이 우선. 게임 내 칩이 포커와 생활/하우징/마을 발전에 공용으로 쓰인다. 이전 10문답의 생활 RPG·판타지 주민·짧은 판타지 포커·관계·집/마을/수집·자유로운 시간·따뜻한 카드 테마 마을 방향을 유지한다.
- **기획 담당의 개발 제안(이번 문서)**: Godot 4 + GDScript, Windows 로컬 플레이 우선, 2D 탑다운 기반 3/4 화면, 5장 원드로 포커, 첫 플레이 15~25분에 해당하는 콘텐츠 흐름. 세부 수치·이름·그래픽은 시험용이며 플레이 검증 후 조정 가능하다.
- **하지 않음**: 실제 화폐/환전/유료 칩 구매/칩의 외부 양도, 온라인 대전, 실제 카지노의 고증 요구, 강제 일일 출석, 타이머에 의한 이벤트 영구 소실. 게임물 등급·유통 적합성은 별도 확인 과제이며, 이 문서만으로 판정하지 않는다.
- 기존 v0.1의 'repository preparation ONLY'는 당시 **작업 지시의 범위**였음. 저장소 준비와 기술 조사 이후의 새 작업 지시는 별도로 내려야 한다. 과거 문서의 본문을 덮어쓰지 않는다.

## 1. 플레이어가 처음 느껴야 하는 것

**핵심 감정**: “이상하지만 정겨운 마을에 살기 시작했고, 어제 만난 주민과 포커를 친 덕분에 오늘 내 집이 조금 달라졌다.”

**증명할 루프**: 마을 도착 → 주민과 인사 → 저녁 포커 체험 → 칩 획득 → 가구 구매 및 집에 배치 → 그 행동을 주민이 기억하고 짧은 후속 대사 제공. 포커에서 패배해도 이 루프가 끊어져서는 안 된다.

**첫 버전 비목표**: 수십 명의 자율 NPC 시뮬레이션, 연애 구현, 건물 전체 건설, 광역 이동, 실시간 멀티, 모바일 정식 UI, 고품질 아트 완성.

## 2. 첫 플레이: 순서·트리거·이탈 경로

| 단계 | 플레이어 행동 | 화면/상태 변화 | 필수 성공 조건 |
|---|---|---|---|
| P0. 도착 | 새 게임 선택, 이름 입력(기본값 제공) | 낮, 작은 마을 입구, 집·광장·포커 모임 장소 표지 | 최초 조작 튜토리얼은 이동·대화 2개만 설명; 건너뛰기 가능 |
| P1. 인사 | 광장의 주민 루미와 대화 | 루미가 플레이어를 알아보고 포커 모임을 안내 | 첫 대화 플래그 저장; 반복 대사 구별 |
| P2. 자유 시간 | 집 확인/마을 걷기/주민 대화 | 낮; 무엇을 할지 강제하지 않음 | 포커 초대는 지도 표지와 대화 메뉴에서 언제든 확인 가능 |
| P3. 포커 모임 | 모임 장소 입장 후 '한 판 해보기' 선택 | 저녁 조명 연출과 포커 UI 진입 | 게임 내 시간대가 낮이어도 초대를 선택하면 저녁 모임 장면으로 이동 가능; 대기 타이머 없음 |
| P4. 짧은 승부 | 초기 5장 확인 → 최대 3장 선택 교체 1회 → 공개·족보 비교 | 족보 설명, 선택 가능 능력 1개, 결과 및 재화 정산 | 조작하지 않아도 단순 안내로 완주 가능; AI는 플레이어의 숨은 카드를 열람하지 않음 |
| P5. 보상 | 승/패/무 결과 확인 | 승 60칩, 무 30칩, 패 20칩(테스트 수치). 첫 참가 보너스 40칩은 결과와 무관하게 1회 지급 | 첫 게임의 패배/동점에서도 다음 단계에 필요한 구매액을 모을 수 있음 |
| P6. 꾸미기 | 상점에서 50칩짜리 작은 등불 구매 → 집의 지정된 슬롯 중 하나에 배치 | 소지 칩 감소, 집 장식 변경 | 첫 참가 후 최소 60칩 확보(패 20 + 보너스 40); 배치 후 저장/재진입 유지 |
| P7. 반응 | 루미에게 다시 대화 | '등불을 놓았구나' 식의 짧은 반응, 수집 도감에 등불 기록 | 최초 대사와 후속 대사가 실제 조건에 따라 달라짐 |
| P8. 자유 플레이 | 포커 다시 치기/집 꾸미기/종료 | 자유 탐색 복귀 | 진행 강제 팝업 없음; 저장 후 종료/재개 가능 |

> 위 수치는 구현 시작용 가설이다. 외부 출시용 경제 밸런스가 아니며 테스트 결과에 따라 변경한다. 포커 참가비는 첫 버전에서 **0칩**으로 둔다. 칩을 모두 써도 무료 게임과 간단한 생활 의뢰로 재획득할 수 있다.

### 선택·실패 처리

- 주민과의 첫 대화보다 포커 장소에 먼저 도착하면, 루미가 그 자리에서 기본 안내를 제공한다. '순서가 틀렸다'는 이유로 진행을 막지 않는다.
- 상점에 먼저 방문해도 구경은 가능하다. 구매 가능 여부를 칩 수로 표시한다.
- 집 방문은 언제든 가능하다. 가구가 없으면 기존 기본 가구만 표시된다.
- 중간 종료 후 재개하면 마지막 저장 상태로 복귀한다. 첫 참가 보너스는 중복 지급하지 않는다.

## 3. 장면·HUD·조작 기준

**게임 화면**: 2D 작은 마을에서 플레이어 이동, 건물 출입, NPC 상호작용. 우선 키보드+마우스: WASD/방향키 이동, E/Enter 상호작용, Esc 메뉴/뒤로, 마우스로 카드와 가구 선택. 화면에 버튼 표시를 병행해 모바일 확장 시 입력 계층 교체가 가능하게 한다.

**HUD 최소 요소**: 현재 칩 보유량, 상황에 따라 나타나는 `E 대화/입장`, 짧은 현재 목표(선택적으로 접기), 메뉴. 체력·허기·일일 행동력·실시간 카운트다운은 없다.

**포커 UI**: 5장 카드; 교체 선택 상태; '교체하기'/'그대로 승부' 버튼; 현재 사용 가능한 판타지 능력 버튼; 작은 족보 도움말; 결과 화면의 칩 증감. 포커 중 공간 이동 조작과 충돌하지 않도록 입력 모드를 분리한다.

**하우징 UI**: 인벤토리에 구매 가구 표시 → 집 진입 → 배치 모드 진입 → 미리 정한 유효 배치 슬롯 선택 → 확정/취소. 첫 버전에서는 완전 자유 그리드/회전/벽 충돌 편집기를 만들지 않는다.

## 4. 테스트용 주민 3명과 공간 4곳

| ID | 임시 이름/종족 | 일상 역할 | 첫 버전의 기능 | 성격을 드러내는 작은 행동 |
|---|---|---|---|---|
| npc_lumi | 루미 / 여우 수인 | 환영·동네 포커 친구 | 첫 인사, 포커 1:1 상대, 가구 배치 후 반응 | 플레이어가 지면 실망시키지 않고 다음 판을 권함 |
| npc_moa | 모아 / 칩 요정 | 포커 모임 안내자 | 규칙 설명, 족보 도움말, 모임 장소 입장 안내 | 게임이 끝나면 카드와 칩을 바쁘게 정리함 |
| npc_sera | 세라 / 마법사 | 작은 상점 주인 | 등불 판매, 기본 상점 UI | 구매한 물건이 집에 놓인 뒤 대사가 바뀜(선택 추가) |

공간: `village_square`(광장·인사), `player_home`(집/하우징), `card_room`(저녁 모임), `small_shop`(가구 구매). 첫 버전은 4곳을 **별도 씬 또는 단순 실내 전환**으로 표현할 수 있다. 실제 맵 면적이나 건물 배치는 그레이박스 단계에서 확정한다. 모든 캐릭터 이름/외형은 제작용 임시안이며 최종 캐릭터 바이블이 아니다.

## 5. 테스트용 포커 규칙 v0 (별도 룰 검증 필요)

- **형식**: 플레이어 대 루미, 1:1, 52장 표준 덱(조커 없음), 각자 5장 배분, 남은 덱에서 최대 3장까지 1회 교체, 최종 5장 족보 비교. 카드의 표시·교체 UI를 먼저 검증한다.
- **승패**: 일반 5장 포커 족보 순위 및 동률 비교를 이용한다. 5장 포커 족보의 전체 우선순위/킥커 비교/무승부 조건을 테스트 파일에 명시한다. 임의로 '높은 숫자만 비교' 같은 단축 규칙을 사용하지 않는다.
- **첫 판 판타지 능력**: `별빛 감각`(플레이어) — 교체 선택 전에 루미의 현재 5장 패가 **원페어 이상인지 여부만** 1회 알려준다. 최종 패·상대 카드·향후 덱 순서는 보여주지 않는다. 전투/도박상 초능력의 세계관 고증은 이번 범위 밖이다.
- **루미의 플레이**: 사전에 정한 공개 가능한 규칙 기반으로 교체 카드를 선택한다. 테스트에서는 패를 몰래 바꾸거나 플레이어의 비공개 패를 읽지 않는다. 다른 주민의 고유 능력과 복잡한 능력 밸런스는 다음 프로토타입 과제다.
- **보상**: 첫 판 참가비 0, 승 60 / 무 30 / 패 20칩, 첫 참가 보너스 40칩(최초 1회). 게임 내 가상 재화일 뿐 현금 가치·현금 구매·외부 이전 수단을 만들지 않는다.
- **테스트 가능성**: 덱 셔플은 시드 고정 주입이 가능해야 하고, 족보 판정은 순수 함수로 분리한다. 동일 시드·동일 선택으로 결과를 재현할 수 있어야 한다.

## 6. 경제·상태·저장 계약

**단일 재화**: `chips_balance`는 0 미만이 될 수 없다. `chips_ledger`는 지급/지출 이벤트를 기록할 수 있어야 한다. 첫 프로토타입에는 유료 상품/마이크로트랜잭션/현금 인출/플레이어 간 거래 없음.

**필수 상태 예시**(세부 파일 포맷은 개발팀이 제안): `player_name`, `chips_balance`, `intro_met_lumi`, `first_poker_bonus_claimed`, `poker_hands_completed`, `owned_items[]`, `home_placements[]`, `lumi_lamp_reaction_seen`, `current_scene`, `save_version`.

**저장 기준**: 신규 시작, 포커 정산, 구매, 가구 배치, 주요 대화 플래그, 종료/재개. 먼저 단일 로컬 세이브 슬롯 + 버전 필드로 충분하며, 신버전에서 구세이브를 거부하는 상황은 테스트할 것. 치팅 방지용 온라인 보안 시스템은 비목표.

**시간 기준**: 그레이박스에서는 낮/밤을 실제 분당 자동으로 흘리지 않는다. 플레이어가 포커 모임을 선택하면 저녁 장면으로 전환하고 마을로 돌아오면 자유 탐색. 전역 게임 달력·실시간 주말 이벤트·NPC 전원 스케줄은 후속 설계에서 다룬다. 플레이어는 언제든 포커에 재진입 가능.

## 7. 아트·연출 기준 — 제작 브리프, 현재 에셋 제작 지시 아님

- 사용자 확정 **A+C**: 아기자기하고 따뜻한 판타지 마을 + 생활 공간 속에 포커 모티브(카드 문양·칩·하트·스페이드)를 자연스럽게 통합. 주민은 인간/판타지 종족/독창적 작은 생명체가 공존한다.
- 앞선 기술 제안의 **2D 탑다운/3·4 시점 + 픽셀풍**은 구현을 시작하기 위한 임시 방향. 사용자가 픽셀아트 자체를 확정한 것은 아니므로, 최종 고품질 에셋 대량 생산 전에 실제 플레이 화면 비율의 아트 목업 1장과 사용자의 비주얼 확인을 별도 단계로 둔다.
- 프로토타입에서는 단순 색면/기본 타일/기호/텍스트 임시 그래픽 허용. 다른 상용게임의 에셋을 무단 복제하지 않는다. 카드 앞·뒷면과 손패 비공개 상태는 UI에서 명확히 구분한다.
- 마을: 따뜻한 자연광, 읽기 쉬운 길/건물 출입구. 포커 공간: 포근한 저녁 조명, 과도하게 카지노 광고를 연상시키지 않는 작은 주민 모임. 선택지/족보 텍스트는 색만으로 구분하지 않는다.

## 8. 단계별 개발 게이트 및 수용 조건

### Gate 0 — 저장소 점검 및 계획 (구현 전)
- 기존 GitHub `main`/문서/기술조사 결과를 확인한다. 이전 문서를 수정하지 않고 이 파일을 `docs/design/`에 추가한다.
- 엔진 버전과 설치 가능 여부, 로컬 실행 방법, 제작 범위·핵심 의존성·테스트 전략·기술적 막힘을 간단히 보고한다.
- 본문에 없는 큰 제품 결정이나 과금/외부 기능은 요청하지 않는다. 기술적으로 막히는 사안만 최소한으로 질문한다.

### Gate 1 — 그레이박스 첫 루프
- PC에서 실행 가능. 마을 → 루미 인사 → 포커 → 보상 → 상점 → 등불 집 배치 → 루미 후속 반응 전체 루프 완료.
- **승리·무승부·패배 각각** 보상과 구매 가능성을 검증한다. 중간 종료/재진입 및 첫 참가 보너스 1회만 지급 검증.
- UI 플레이 중 막힘, 중복 정산, 음수 칩, 세이브 유실, 포커 족보 오판, 숨은 정보 악용이 없어야 한다.
- 세이브/족보/보상/인벤토리/가구 배치 조건을 자동 테스트하거나 재현 가능한 수동 절차로 기록한다.

### Gate 2 — 플레이어 시각 검수 (Gate 1 이후)
- 스크린샷/짧은 플레이 캡처와 조작 방법을 보고한다. 마을 1컷, 포커 1컷, 가구 배치 1컷이 필요하다.
- 첫 플레이가 '포커 때문에 집/관계가 변한다'는 느낌을 주는지 확인한다. 미흡하면 시스템을 무작정 추가하지 말고 루프의 반응을 고친다.
- 고품질 아트/다수 NPC/연애/멀티플레이/모바일/배포/Steam 연동은 별도 작업 지시 전 시작하지 않는다.

## 9. 개발자에게 요구하는 완료 보고

1. 사용한 저장소 브랜치/커밋과 바꾼 파일 목록.
2. 직접 실행한 명령, 실행 환경, 통과/실패 테스트, 확인하지 못한 항목.
3. P0~P8 중 구현된 구간과 미구현 구간.
4. 스크린샷 3종 및 실행 방법(가능한 경우).
5. 기획과 다른 결정이 있었다면 변경 이유와 파급 영향. 임의로 전체 기획을 바꾸지 말 것.
