# 개발 실행 순서 — 1~6단계 콘텐츠 통합, 비주얼은 7단계

## Stage 0 준비
최신 `main`의 CLAUDE.md, save_version, scene ID, 주민/아이템 실제 ID 확인. 기존 v0.2.2 경제와 포커 복원 테스트를 baseline으로 고정. 새 브랜치에서 기능별 커밋 후 테스트/문서 갱신, 기존 기획 문서 원본 유지.

## 1. 세계관 구현
주 서사 3막의 `story flags`, 자료/기여, 행사의 다시 보기 데이터 및 핵심 대화. 첫 루프와 포커0판 완주 경로 테스트. 01_world 문서와 06/04 선행표를 사용.

## 2. 마을 구현
5개 지구, 17개 기능 공간/상호작용. 기본 NPC/건물은 임시 도형 재사용. 지구 포털·스폰·충돌·지구당 되돌아오기·시간 유지 테스트.

## 3. 주민 구현
신규 13명 등록 후 주민 총16명, 단일 위치/스케줄, 관계 축 분리, 개인 사건32개, NPC 간 등록 간선, 선택적 연애. 모든 주민이 2건의 실제 사건을 제공해야 하며 텍스트 파일 생성만으론 불충분.

## 4. 생활 구현
집 확장3, 공공사업8, 일거리4, 의뢰16, 아이템64·도감6. 기존 등불/퀘스트/직업을 신규 id로 중복 추가하지 말고 매핑. 경제·세이브·취소/중단 검증.

## 5. 포커 구현
기존 원드로 룰/경제 유지, 상대10, 능력8, 모드3, 대회1. 각 상대의 공개 정보 제한과 복원/정산 테스트 필수. 포커 없이 스토리 해금 가능한지 지속 확인.

## 6. 통합 구현
행동→기억→대사→월드 변화 12연결, 메인 3막/후일담, 포커0·파산·연애거절·행사재방문·구세이브 등 12 E2E 경로. 자동 테스트와 실제 수동 완주 모두 필요.

## 진행·중단
단위 작업이 끝날 때마다 기존 테스트 포함 검증 후 커밋/푸시. 오너에게 매번 미술 검수/독립exe/스크린샷 재요청 금지. **기획 위반/저장 유실/배포 라이선스 문제처럼 중요 결정이 필요한 때만 질문.** 6단계 완료 보고 전 고품질 비주얼/Steam/모바일/온라인 개발 금지.
