# PROJECT 20 — Economy v0.2.1 (승인됨)

| 항목 | 내용 |
|---|---|
| 상태 | **기획 승인 확정값** (2026-09-25, 프로젝트 오너 전달) |
| 적용 범위 | 칩 경제. 명세 v0.2와 충돌하면 칩 경제에 한해 이 문서가 우선 |
| 대체하는 내용 | 명세 v0.2 P5·5절의 승 60 / 무 30 / 패 20, 첫 참가 보너스 40, 참가비 0 |
| 데이터 위치 | `game/data/poker.json` → `economy`, `game/data/quests.json`, `game/data/jobs.json`, `game/data/items.json` |

아래 1~5절은 승인 내용을 그대로 옮긴 것입니다. 6절은 개발 측 구현 대응표입니다.

---

## 1. INITIAL ECONOMY

| 항목 | 값 |
|---|---|
| 게임 시작 칩 | 100 |
| 포커 참가금 | 20 |
| 포커 승리 | 총 40칩 반환 (참가금 포함, 순이익 +20) |
| 포커 패배 | 0칩 반환 (순손실 -20) |
| 포커 무승부 | 참가금 20칩 반환 (순손익 0) |
| 첫 참가 보너스 | 없음 |
| 일회성 주민 의뢰 완료 보상 | 30칩 |
| 반복 가능한 아르바이트 완료 보상 | 10칩 |
| 등불 가격 | 기존 50칩 유지 |

## 2. POKER SETTLEMENT

- 플레이어와 NPC가 각각 20칩을 걸고, 승리한 쪽이 총 40칩을 획득하는 구조입니다.
- 플레이어의 참가금 20칩은 게임 시작 시 차감합니다.
- 승리하면 40칩을 지급하고, 무승부라면 20칩을 반환하며, 패배하면 추가 지급하지 않습니다.
- 패배에 대한 별도의 위로 보상은 없습니다.
- 포커 참가 시 보유 칩이 20칩 미만이면 참가할 수 없습니다.
- NPC의 개인 자산 및 파산 시스템은 구현하지 않습니다. 이번 프로토타입에서는 상대 NPC의 참가금과 정산을 게임 시스템에서 처리합니다.

## 3. RECOVERY LOOP

- 플레이어가 모든 칩을 잃더라도 반복 가능한 생활 아르바이트에 참여할 수 있어야 합니다.
- 아르바이트는 참가 비용 없이 진행하며, 정상적으로 완료할 때마다 10칩을 지급합니다.
- 잔액이 0칩이어도 아르바이트에 참여할 수 있고, 두 번 완료하면 다시 포커에 참가할 수 있습니다.
- 아르바이트의 보상은 실제 활동 완료 시에만 지급하며, 상호작용 버튼만 반복해서 누르는 것으로 보상을 무한 획득할 수 없도록 구현합니다.
- 일회성 주민 의뢰는 최초 완료 시에만 30칩을 지급합니다.

## 4. DATA & SAVE

- 경제 수치는 가능한 한 기존 JSON 데이터 구조를 활용하여 관리합니다.
- 포커 참가금 차감과 승부 결과 정산 과정에서 칩이 중복 지급되거나 사라지지 않도록 처리합니다.
- 게임 중단 및 재실행, 저장과 불러오기, 의뢰 완료 상태 복원 시에도 중복 지급이 없어야 합니다.
- 기존 저장 파일을 사용할 경우에는 기존 칩 잔액을 임의로 100칩으로 초기화하지 않습니다.
- 신규 게임에 대해서만 시작 칩 100개를 적용합니다.
- 기존 게임 저장 데이터와 충돌하는 부분은 마이그레이션하거나, 문제가 발생할 경우 보고합니다.

## 5. EXECUTION

- 위 수치를 기획 승인된 확정값으로 취급합니다.
- 기존 명세와 이번 승인 내용이 충돌하는 경우, 칩 경제에 한하여 이번 승인 내용을 우선 적용합니다.
- 기획 문서 원본은 수정하지 않고, 이번 결정은 별도의 경제 설계 문서(이 문서)에 기록합니다.

## 6. 구현 대응 (개발 담당 기록)

| 승인 항목 | 데이터 키 | 구현 위치 |
|---|---|---|
| 시작 칩 100 (신규 게임만) | `poker.json economy.starting_chips` | `Game.new_game` |
| 참가금 20, 시작 시 차감 | `economy.stake` | `PokerEconomy.place_stake` (`GameState.pending_poker_stake`에 기록 후 저장) |
| 승리 40 / 무승부 20 / 패배 0 반환 | `economy.payout_win/draw/lose` | `PokerEconomy.settle` |
| 20칩 미만 참가 불가 | `economy.stake` | `PokerEconomy.can_join` |
| 의뢰 30 (최초 1회) | `quests.json reward` | `QuestBook.complete` (active → completed일 때만 지급) |
| 아르바이트 10 (완료 시) | `jobs.json reward` | `PlazaJob.collect` (5개 지점을 모두 주운 순간에만 지급) |
| 등불 50 | `items.json price` | 변경 없음 |
| 기존 저장 파일 잔액 유지 | — | `SaveSystem._migrate` v1 → v2 (잔액 그대로, 시작 칩 미적용) |

**거래 기록(원장) 사유 코드:** `starting_chips`, `poker_stake`, `poker_payout_win`, `poker_payout_draw`, `poker_void_refund`, `quest:<id>`, `job:<id>`, `buy:<item>`. 패배는 반환이 0칩이라 원장 항목이 생기지 않고, 참가금 차감(`poker_stake`)만 남습니다.

**승인 문서에 명시되지 않아 개발 측이 정한 처리** (기획 확인 요청 사항, [Design Correction 02](Project20_Design_Correction_02.md) 5절):
- 승부 전에 자리에서 일어나거나 창을 닫으면 **포기(폴드)**로 처리하고 참가금을 돌려주지 않습니다.
- 프로세스 강제 종료처럼 판이 정산되지 못한 경우에는 다음 불러오기 때 **참가금을 1회 환불**합니다.
