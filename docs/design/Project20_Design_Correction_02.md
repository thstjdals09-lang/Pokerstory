## 1. 기존 구현과 기획 의도의 불일치

| # | 기존 구현 (v0.2 프로토타입) | 기획 의도 | 원인 |
|---|---|---|---|
| 1 | 패배해도 +20칩, 첫 참가 +40칩, 참가비 0 | 포커는 칩을 **걸고** 이기면 얻고 지면 잃는다 | 명세 P5의 테스트 수치를 그대로 구현하면서 "지더라도 루프가 끊기지 않게"를 **포커 보상으로** 해결했습니다. |
| 2 | 생활 의뢰 미구현 ("포커로 재획득 가능하니 루프는 유지된다"고 보고) | 칩을 모두 잃어도 **포커 밖의 생활 활동**으로 다시 모을 수 있어야 한다 | 1번 해석을 근거로 필수 시스템을 선택 사항으로 취급했습니다. 1번과 연결된 오류입니다. |
| 3 | 루미가 광장과 카드룸에 **동시에** 존재 | 한 주민은 한 시점에 한 장소에만 있다 | 스케줄 시스템이 없다는 이유로 두 장소에 고정 배치했습니다. |
| 4 | 카드룸에서 나오면 마을이 **낮으로 초기화** | 시간대는 장소를 옮겨도 유지된다 | 시간을 전역 상태가 아니라 장소별 조명 속성으로 구현했습니다. |

## 2. 수정한 포커 경제 구조

[Economy v0.2.1](Project20_Economy_v0.2.1.md)을 그대로 적용했습니다.

```
참가 (보유 칩 ≥ 20일 때만)   → 보유 칩 -20 (즉시 차감·저장, 미정산 참가금으로 기록)
승부 결과  승리             → +40  (순이익 +20)
          무승부           → +20  (순손익 0)
          패배             →  +0  (순손실 -20)
승부 전 자리 떠나기 / 창 닫기 → 포기: 반환 없음 (순손실 -20)
판 도중 비정상 종료          → 다음 불러오기 때 참가금 20칩 1회 환불
```

- 제거: 패배 보상 +20, 첫 참가 보너스 +40, 고정 지급(승 60 / 무 30).
- 새 게임은 100칩으로 시작합니다. 기존 저장 파일(v1)은 잔액을 그대로 유지합니다.
- 모든 칩 변동은 기존 거래 기록(원장)에 남습니다.
- 한 판은 `정산`, `포기`, `환불` 중 정확히 한 번만 처리됩니다. 미정산 참가금이 남아 있는 동안에는 새 판을 시작할 수 없습니다.
- 포커 화면에 판돈(나 20 + 루미 20)과 보유 칩을 표시합니다. 결과 화면에는 획득·반환·손실 금액과 순손익을 표시합니다. 칩이 부족하면 "한 판 더" 버튼이 "칩 부족 (20 필요)"으로 바뀌고 비활성화됩니다.

## 3. 생활 의뢰와 반복 활동

### A. 일회성 주민 의뢰 — "세라의 꾸러미 배달"

| 단계 | 내용 |
|---|---|
| 받기 | 세라의 잡화점에서 "무슨 일인데요? / 부탁하실 일 있으세요?" → 의뢰 설명 → "맡을게요" |
| 진행 | HUD 목표: "루미에게 마법 불씨 꾸러미 전해 주기 (낮: 광장 · 저녁: 카드룸)". 세라에게 다시 말 걸면 안내 |
| 완료 | 루미(낮에는 광장, 저녁에는 카드룸)에게 말 걸기 → "꾸러미 건네기" → **30칩**(최초 1회) → 루미의 감사 대사 |
| 이후 | 세라가 1회 감사 인사. 의뢰 선택지는 더 이상 나오지 않음 |
| 중복 방지 | 보상은 상태가 `active → completed`로 바뀔 때만 지급. 완료 상태는 저장되며, 다시 받거나 다시 완료할 수 없음 |
| 저장 | `GameState.quests`에 `{quest_id: "active" \| "completed"}`로 저장 |

데이터: `game/data/quests.json`, 대사는 `dialogue.json`(`sera_quest_offer`, `sera_quest_active`, `sera_quest_done`, `lumi_quest_delivery`, `lumi_quest_thanks`).

### B. 반복 아르바이트 — "광장 정리 아르바이트"

| 항목 | 내용 |
|---|---|
| 시작 | 광장의 **아르바이트 게시판**에서 "아르바이트 시작하기". 칩 0개여도, 포커를 한 번도 안 했어도, 낮이든 저녁이든 가능 |
| 활동 | 광장 여러 곳(후보 8곳 중 무작위 5곳)에 흩어진 카드와 칩을 **직접 걸어가서** 하나씩 줍기(E) |
| 완료 | 5개를 모두 주운 순간 **10칩** 지급. 원장 사유 `job:job.plaza_cleanup` |
| 반복 | 제한 없이 다시 시작할 수 있음 |
| 무한 획득 방지 | 한 지점은 한 번만 주울 수 있고, 줍기 범위(반경 34)보다 지점 간 거리가 멉니다(최소 68 초과, 단위 테스트로 확인). 같은 자리에서 E를 반복해도 1개만 인정되고, 게시판을 눌러도 보상은 없습니다. 보상은 마지막 지점에서만 나옵니다. |
| 중단 | 광장을 떠나면 진행이 취소되고 보상이 없습니다. 진행 중 상태는 저장하지 않으므로, 불러오기로 반쯤 한 아르바이트를 이어서 보상을 받을 수 없습니다. |

0칩에서 두 번 완료하면 20칩이 되어 포커에 다시 참가할 수 있습니다(E2E `broke` 시나리오로 확인).

## 4. 시간대와 NPC 위치

| 항목 | 구현 |
|---|---|
| 시간 상태 | `GameState.time_of_day` = `day` / `evening`. 저장·불러오기 |
| 장소 이동 | 시간은 장소를 옮겨도 유지됩니다. 저녁에는 모든 장소에 저녁 조명이 적용되고, HUD에 "저녁 · 장소명"이 표시됩니다. |
| 루미 | 낮: 광장 / 저녁: 카드룸 (`locations.json`의 배치별 `time`). 모아는 저녁 카드룸, 세라는 상시 잡화점 |
| 중복 배치 방지 | 데이터 검증이 "한 주민이 같은 시간대에 두 장소"를 오류로 거부합니다. 월드는 현재 시간대에 맞는 배치만 생성합니다. |
| 시간 바꾸기 | ① 카드룸 문(낮): "저녁까지 기다렸다가 들어가기" → 저녁 ② 집 침대(낮): "저녁까지 쉬기" → 저녁 ③ 집 침대(저녁): "아침까지 자기" → 낮 |
| 강제 진행 | 없음. 시간은 플레이어의 선택으로만 바뀝니다. |
| 카드룸 | 저녁에만 입장할 수 있습니다(모임 시간). 낮에 문에서 E를 누르면 안내와 선택지가 나옵니다. |
| 기존 저장 파일 | v1 → v2 변환 시 시간은 낮으로 시작하되, 카드룸에서 저장한 파일은 저녁으로 변환합니다. |

## 5. 개발 측이 정한 처리 — 기획 확인 요청

지시서와 승인 문서에 명시되지 않아 개발 측이 정한 부분입니다. 다르게 원하시면 데이터나 소규모 수정으로 바꿀 수 있습니다.

| # | 결정 | 이유 | 대안 |
|---|---|---|---|
| D1 | 승부 전에 자리에서 일어나면(버튼 또는 창 닫기) **포기 = 참가금 손실** | 나쁜 패를 보고 나가서 참가금을 돌려받는 우회를 막기 위해서입니다. 나가기 전에 확인 창으로 경고합니다. | 나가면 환불 (우회 가능) |
| D2 | 프로세스 강제 종료 등으로 정산되지 못한 판은 다음 불러오기 때 **참가금 1회 환불** | "칩이 사라지지 않도록" 요구에 맞추기 위해서입니다. 원장에 `poker_void_refund`로 남습니다. | 포기로 처리 (칩 손실) |
| D3 | 카드룸은 **저녁에만** 입장 가능, 낮에는 문 앞에서 "기다리기"로 저녁 전환 | 명세 P3("초대를 선택하면 저녁 모임 장면으로 이동")와 "시간대 직접 변경" 요구를 함께 만족시키기 위해서입니다. | 낮에도 입장 가능하되 빈 방 |
| D4 | 루미를 처음 만나는 경우 **첫 인사가 의뢰 전달보다 먼저** 나오고, 다시 말을 걸면 전달 | 첫 만남 대사를 건너뛰지 않기 위해서입니다. | 첫 인사에 전달 선택지 추가 |
| D5 | 아르바이트는 5개 줍기, 광장을 떠나면 취소, 반복 제한 없음, 진행 중 상태는 저장 안 함 | 명세의 "간단한 프로토타입 수준"과 무한 획득 방지 요구를 함께 만족시키기 위해서입니다. | 하루 횟수 제한 등 (현재 시간 진행이 선택 기반이라 효과가 약함) |
| D6 | 의뢰 물품(꾸러미)은 인벤토리 아이템으로 만들지 않고 의뢰 상태로만 관리 | 신규 아이템·UI 없이 요구를 충족하기 위해서입니다. | 인벤토리에 꾸러미 표시 |
| D7 | 모아는 저녁 카드룸에만 배치 | 카드룸이 저녁에만 열리므로 실제 차이는 없습니다. | — |

## 6. 검증

자동 테스트 결과는 [FIRST_PLAY_BUILD_NOTES.md](../dev/FIRST_PLAY_BUILD_NOTES.md) 4절에 있습니다. 지시서 5절의 검증 항목 대응은 다음과 같습니다.

| 검증 항목 | 확인 방법 |
|---|---|
| 포커 승리 시 칩 증가 / 패배 시 감소 / 무승부 정상 정산 | 단위 `test_win_increases_draw_keeps_loss_decreases`, E2E win/draw/lose (+20 / 0 / -20) |
| 칩 부족 시 참가 제한 | 단위 `test_cannot_join_below_stake`, E2E broke (0칩에서 "한 판 더" 비활성, 모아 선택지 거부) |
| 칩 0개에서 생활 활동으로 재기 | E2E broke (0 → 아르바이트 2회 → 20 → 재참가 → 승리 40) |
| 일회성 의뢰 중복 보상 방지 | 단위 `test_quest_pays_once`(저장·불러오기 포함), E2E resume_c (재실행 후 재대화, 원장의 의뢰 지급 1건) |
| 반복 활동 정상 보상 | 단위 `test_job_pays_only_after_every_spot`, `test_job_is_repeatable_from_zero_chips`, E2E broke (반복 입력 무효, 취소 시 무보상) |
| 장소 이동 후 시간대 유지 | E2E win/draw/lose (카드룸 → 마을 → 잡화점 → 집, 저녁 유지) |
| 주민 중복 배치 방지 | 데이터 검증 + 단위 `test_each_resident_is_in_one_place_per_time`, E2E (저녁 광장에 루미 없음, 낮에 복귀) |
| 저장·불러오기 후 상태 유지 | E2E (저녁 상태로 재시작), resume_a/b/c (미정산 참가금 환불 1회, 의뢰 진행 상태 복원), migrate (v1 잔액 유지) |
