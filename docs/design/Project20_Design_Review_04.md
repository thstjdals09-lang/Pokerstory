## 1. 결정

### R1 — 승인

- 참가금은 게임 안에서 **명시적으로 포기**를 선택했을 때만 잃습니다(포커 화면의 "나가기" → 확인 창 → "나가기").
- 창 닫기, 메뉴를 통한 종료, 비정상 종료 시에는 진행 중인 판을 저장했다가 재실행 시 복원합니다.
- 손패, 덱, 능력 사용 여부, 참가금, 진행 상태는 바뀌지 않아야 합니다.

**구현 상태:** Design Review 03 빌드에서 이미 이렇게 동작합니다. 포커 화면에서는 메뉴가 열리지 않으므로(Esc는 포기 확인 창), 판 도중 메뉴로 종료하는 경로는 없습니다. 메뉴 종료는 판이 없을 때만 가능합니다.

**이번에 추가한 검증:** 판 도중 창 닫기 요청(`NOTIFICATION_WM_CLOSE_REQUEST`)을 보냈을 때, 저장 파일에 손패와 미정산 참가금이 그대로 남고 포기 기록이 생기지 않는지 확인합니다(E2E `path_d1`).

### R2 — 조건부 승인

- 참가금만 차감되고 손패가 저장되지 않은 **기존 v2 저장 파일에 한해**, 추가 참가금 없이 새 판을 한 번 제공합니다.
- 이전 저장 파일 호환을 위한 일회성 예외이며, 정상적인 v3 저장 파일에는 적용하지 않습니다.
- 같은 저장 파일을 반복해서 불러오는 방법으로 새 손패를 계속 받을 수 없어야 합니다.

## 2. R2 조건 반영 (코드 변경)

**점검 결과:** Design Review 03 빌드는 저장 파일 **버전과 무관하게** "참가금은 있고 카드는 없는" 상태면 새 판을 줬습니다. 정상적인 v3 파일에서는 참가금과 카드를 함께 저장하므로 이 상태가 생기지 않습니다. 하지만 손상되거나 편집된 v3 파일에서는 새 판을 받을 수 있었으므로 조건에 맞게 막았습니다.

| 저장 파일 | 참가금만 있고 카드가 없을 때 |
|---|---|
| v1·v2 (이전 빌드) | 새 판 1회 제공 (추가 차감·환불 없음) → **즉시 v3로 다시 저장**하면서 그 판을 기록 |
| v3 | **손상된 파일로 거부**합니다. 새 판도, 환불도 없고, 파일은 수정하지 않습니다. |

- **반복 로드 방지:** 새 판을 준 순간 저장 파일이 v3가 되고 그 판이 기록됩니다. 같은 파일을 다시 불러오면 그 판이 그대로 이어지고, 새 판을 다시 받지 않습니다.
- **변경 위치:** `SaveSystem.load_state`가 원래 버전(`original_version`)과 예외 대상 여부(`legacy_stake`)를 반환합니다. `Game.load_game`은 `legacy_stake`일 때만 새 판을 제공합니다.

**남는 한계:** 게임 밖에서 원본 v2 파일을 복사해 두었다가 되돌리는 방식은 오프라인 게임에서 막을 수 없습니다. 다만 v2 파일은 이전 빌드에서만 만들어지고, 현재 빌드는 v2 파일을 만들지 않습니다.
